# 系統設計

!!! warning "上流設計目標"
    本節摘要自倉庫根目錄的 `SYSTEM.md` 上流設計。規模、造價、硬體、演算法參數均為**設計取值**，
    本 demo 僅實作其中一小部分。

## 設計原則

1. **算力精準剝離與最小化下沉**：檢測與偽追蹤去重下沉端側，特徵抽取下沉邊側，海量向量檢索與
   離線聚類置於雲側算力，業務邏輯與全量儲存留存業務雲。
2. **絕對去重與無解碼傳輸**：端側偽追蹤剔除 95% 冗餘幀，邊側直收 JPEG 小圖提特徵，雲側徹底
   擺脫 RTSP/GB28181 影片硬解碼開銷。
3. **計算與業務儲存物理隔離**：AI 算力機房保持無狀態／低狀態極速計算，與業務／儲存機房分離。
4. **動靜分層與分時複用**：白天跑 15,000 QPS 實時向量近鄰檢索，凌晨空閒期切出 GPU 跑聚類。
5. **容器化封裝與 K8s 統一編排**：全部計算單元以標準 Docker 鏡像封裝，邊側 K3s、雲側 K8s 統一編排。

## 三級協同

```
10,000 台 智能 IPC  ──(B) 256×128 抓拍小圖──►  33 街區邊緣節點  ──(C) 128 維向量──►  Re-ID 算力機房
   （檢測・IoU 偽追蹤・去重）                    （無解碼特徵抽取・本地布控比對）        （實時檢索・凌晨聚類）
```

| 層 | 職責 | 硬體 | 輸出 |
| :---- | :---- | :---- | :---- |
| 端側 IPC | 1080P@15fps 檢測，IoU 偽追蹤僅在入幀/姿態變化/出幀裁圖 | 0.5 TOPS INT8 NPU | 1.5 張/秒・去重率 95%+ |
| 街區邊緣 | HTTP/MQTT 直收抓拍小圖提特徵，與本地黑名單毫秒比對 | 30〜50 TOPS（2×RK3588） | 128 維 Float32 |
| Re-ID 算力機房 | 15,000 QPS 寫入・CAGRA/HNSW 檢索，凌晨 GPU 圖聚類 | 24 台 / 8 機架・48×L4/L40S | Global_Person_ID |

## 雙機房與 24 小時分時

- **業務／儲存機房**：NVR 影片儲存、業務 API、權限/日誌、Mamba 訓練、全量冷庫。
- **Re-ID 算力機房**：將 24 小時內未合併 ID 的向量常駐 VRAM 做高速檢索。
- **分時運行**：06:00–02:00 實時檢索；02:00–05:00 觸發 Flush → GPU 並查集 + Louvain，將當日
  1.3 億條歸併為 Global_Person_ID → 推送約 1.5 GB 索引至業務機房 → 擦除 24h 前舊資料。

## Mamba 時空約束剪枝

外觀極似（`S_visual = 0.92`）但跨攝像頭時空轉移不合邏輯（`S_mamba = 0.02`）時，判為誤報剔除。

```
S_final = S_visual × σ(W · S_mamba + b)
```

冷啟動增強：幾何鄰近掩碼（隨機 mask 20〜30% 中間卡口）、OSM 路網偽路徑生成、
Cam_Embedding + Continuous_Geo_Embedding 疊加高斯空間擾動。

## 毫秒級布控（黑名單告警）

將「正向檢索」切換為「內存常駐目標 + 資料流穿透比對」的反向匹配架構。

- 以 Pulsar/Kafka Compacted Topic 在 50ms 內完成布控訂閱更新。
- 算力機房將布控向量常駐 GPU VRAM 做 GEMM 比對（單次 < 0.5ms）。
- 邊緣與本地內存黑名單（~2.5MB）做 SIMD 比對，命中時經 MQTT 直達現場終端（50〜100ms）。
- 以 `Watchlist_ID + Camera_ID` 的 5 分鐘滑動視窗防抖，Tombstone 訊息 10ms 全網撤控。

## Smart Gateway 路由

對上層圖偵平台屏蔽雙機房與向量計算細節。

| 場景 | 路徑 |
| :---- | :---- |
| 僅近 24h | 向算力機房發起 Milvus/CAGRA 近鄰檢索（不依賴 ID） |
| 僅 24h 前 | 查業務機房 Global_Person_ID（SQL/ES）或歷史冷庫 |
| 跨 24h | 併發兩側 → 按時間戳排序、剔除異常時空噪點 → 還原完整軌跡 |

!!! note "與本 demo 的對應"
    `reid_sys/api.py` 是此閘道的縮形：屏蔽 backbone / store 細節，以單機房、單進程運行
    （Mamba、冷庫分流未實作）。

## 運維與容災

- 邊緣斷網續傳：512GB NVMe Ring Buffer 本地緩存 48 小時向量，恢復後自動續傳。
- 算力機房 HA：Milvus 多 Replica、C 類 3 秒切流、B 類 MinIO EC 6+2（容忍同時損壞 2 台）。
- 雲邊統一 OTA：經 K3s / K8s 一鍵灰度下發與無感滾動升級。
